## 1. 目标与完成定义

最终产品是本机运行、通过 ChatECNU 使用文本与视觉模型的星露谷智能 Agent。它应当能从 Wiki 图文建设可维护的多模态知识图谱，再基于固定知识版本处理文字、局部图片、用户条件和组合任务。

本轮必须完成三个层次的工作：

1. **核心工程可靠。** 图谱身份、关系、条件、视觉对应与来源可追溯；批量和增量处理正确；Agent 能动态调用通用工具、管理状态、明确报告未完成目标。
2. **产品流程可使用。** 用户可以上传框选、确认身份、提出知识和计算要求、修改条件、查看依据；建库人员可以审阅图文、处理冲突和发布限定范围的知识。
3. **价值有独立证据。** 通过预先定义的场景、变体、反例和受控对照，分别测量知识正确性、图片帮助、图结构帮助和完整任务效果。保留失败及无增益结果。

“代码测试通过”“候选演练完成”“人工审核通过”“正式评测达标”分别记录。完成若干成功示例不等于完成产品验收；本计划也不预设图谱方法一定优于所有基线。

首个发布范围可以小，但必须围绕通用能力选择，并完整披露输入条件和未覆盖分支。小范围发布不取消 V3 的后续功能与验收要求。

## 3. 保持的架构与边界

### 3.1 知识构建链

冻结来源 → 文本/表格子图与真实像素观测 → 实体/状态/关系对齐 → 规范化、融合与质量检查 → Semantica 构图和来源存取 → 候选审阅 → 按能力与条件发布 → 派生索引。

统一记录仍包括 Entity、Fact、Relation、ImageAsset、ImageOccurrence、ImageRegion、VisualObservation、VisualAlignment、Evidence。关系保留方向、谓词和条件，允许单独被视觉对齐与证据引用。资产、页面出现位置、区域、观测和对齐不得混为同一对象。

mKG-RAG 提供方法与已验证的部分原组件；领域适配层负责本项目的抽取、对齐和校验；Semantica 真实参与构图、持久化与来源管理。原组件运行、接口适配、领域实现继续分列。引入 Semantica 原生算法须先有问题样本和隔离对照，不能用启用模块数量衡量融合质量。

### 3.2 Agent 链

用户原文及确认状态 → 可追溯的任务目标记录 → 单 Agent 按需调用识别、检索、补查、澄清、计算工具 → 当前版本结果与声明证据映射 → 全目标覆盖检查 → 完成/部分完成/待输入/不支持/失败的明确回答。

任务目标记录是运行时预测，不是正式评分真值。工具选择保持动态，不按题号、问句或作物名称编写专用主流程。计算值由工具产生；知识解释保留独立证据支持，不能因计算成功而丢弃。

### 3.3 不扩大的范围

不新增重型本地模型、原版 QM 训练、默认 EGTR 部署、产品多 Agent、全屏农场自动理解、自动数量品质识别、存档修改、全局最优经营或复杂排产。支持的有限比较必须声明共同条件。没有工期、人时或日历排期。

## 4. 共用契约

### 4.1 版本与失效

- 知识快照不可变；规范化输出新快照和旧新 ID 映射，保留历史来源与迁移理由。
- 规则批准绑定实现指纹；结果记录实际使用的规则指纹。
- 证据、目标完成状态、计算结果和最终答案绑定任务修订与知识快照。
- 输入、目标、确认身份或选中区域变化时，受影响的旧证据、结果及完成状态统一失效；旧记录可审计但不能继续当作有效结果。
- 图数据、来源、资产与索引版本必须一致；发布失败不得切换当前正式指针。

### 4.2 三种完备性

1. **结构完备：**引用存在，目标类型合法，区域/观测/出现位置对应的资产一致，哈希与版本正确。
2. **审核完备：**正式使用的关键记录与规则有匹配版本的真实批准；自动校验保持自动状态。
3. **语义依赖完备：**所需事实、关系、公式、条件、例外与派生依据完整。区分 AND 必需项、OR 可替代项和条件分支；无基础依据的循环不能自证。

缺用户参数返回待输入；缺知识、缺审核、条件不支持分别报告。一个未审替代分支不应禁用已审分支，但不得因此宣称比较覆盖所有方案。

### 4.3 目标与结果

每个目标至少携带 ID、用户轮次/原文引用、目标类型、对象/条件、预期输出、当前状态和实际结果引用。模型不能直接把目标标为满足；满足状态由当前版本结果及通用约束检查导出。

结果必须区分用户确认输入、检索事实和上游计算派生值。预留方案有稳定计划身份；比较必须具有一致对象、数量、品质和前提，不能混用不同库存副本。

## 6. 样例与价值证明

每个用例保存原始输入、可见信息、全部目标、允许澄清、条件、逐轮状态、来源、预期结果、实际轨迹、失败分类和运行模式。预期结果从原始资料及独立核算建立，不能调用被测函数生成标准答案，也不能从 Agent 自己的目标清单反推。

| 场景 | 正常与变体 | 反例/纠正 | 需要证明的价值 |
|---|---|---|---|
| 知识与依据 | 不同作物、别名、跨页用途、条件说明 | 错前提、缺知识、同名歧义 | 回答有支持且条件完整 |
| 确定性计算 | 售价、生长、加工、材料、阶段区间 | 缺参数、错误单位、不支持职业/加速 | 正确数字及适用范围，而非只会调用工具 |
| 多目标组合 | 预留后比较出售/加工并解释条件 | 短缺、漏一种方案、跨计划混用 | 用户全部可支持目标完成，库存约束保持 |
| 不知名称的图片 | 已知实体的新背景/缩放/遮挡截图 | 模糊、库外、相似候选、用户纠正 | 相对纯文字入口减少名称输入或查询成本 |
| 生长阶段 | 可辨别阶段、结合阶段规则给剩余范围 | 共享幼苗像素、未知阶段内时间 | 合理候选/区间与拒绝过度精确的判断 |
| 问题相关检索 | 同图异问、同问换图、跨页条件 | 错图、缺图、删除关键关系/来源 | 检索使用真实图文，并按问题选择证据 |
| 多轮任务 | 改数量、品质、实体、目标、ROI | 取消、恢复、旧引用、工具失败 | 更改后正确重算，旧答案与完成标记失效 |
| 完整工作台 | 上传框选→确认→用途问答→比较→改条件→看依据 | 无效上传、无候选、缺参数、模型中断 | 普通用户能完成任务，过程与错误可理解 |

### 6.1 图文建图评测

分开统计文本事实/关系、结构锚点、阶段序列示意、模型对齐和复合图对齐。评价正确性、覆盖、条件保留、区域定位、来源支持和冲突处理。结构模式、模型模式、自动结果及人工修正后结果分列。少量复合图案例不外推总体精度。

必须另有未参与实现的新页面组，覆盖物品、作物阶段与关系图解；两个互不重叠的增量批次沿用 V3 要求，Radish 两页诊断不能代替全部批次。冻结原始页面、图片、区域及来源修订，独立标注实体、状态、关系方向、条件与允许的空视觉关系，再比较纯文本、结构锚点和真实像素融合。分别保存自动图、人工修改差异与重建图，报告错误合并、错区域、无依据关系和条件遗漏，不能只比较节点数量。

批次A可用于通用适配；适配冻结后批次B不能逐页补规则再报泛化。V3的K0仍保留DOM图注/链接等结构信息；新增纯文本组是额外消融，不能偷换原K0定义。

补齐一条来源变化的端到端证据链：取得可核验的新旧来源修订 → 新版抽取与融合 → 失去有效支持的旧贡献及派生记录失效 → 新快照下 Agent 正确采用变化 → 旧任务仍能按旧快照回放。其他来源仍支持的共享事实须保留；格式改动而语义不变时答案也应不变，实质内容变化才要求相应答案变化。可以使用可验证的真实历史修订对，无须等待未来更新。人为改值只作为工程扰动测试；如果没有真实可验证修订，真实修订项保持待验，不能改名为通过。

### 6.2 图片评测划分

- 图库可以包含已知实体的标准 sprite；真实新截图出现同一 sprite 是合法测试。
- 同一原截图、视频采集会话及其裁剪/变换属于同组，不能跨调参与测试。
- 原图简单缩放或背景合成只作为合成回归，不冒充独立实景截图。
- 记录截图族、来源、实体、图库模板、采集方式、游戏版本及标注状态。未知阶段不强制标为唯一身份。
- 建图新页面泛化、已知实体新截图、扩库后新实体、图库外拒识分别报告。
- 同时报告自动接受精度、接受覆盖率、错误接受、拒识、候选集合大小、确认后成功和交互负担，防止全部拒识掩盖无用。
- 可公开取得的真实图片继续采集；不可确认的来源/标签留待审，不用模型生成图填充正式视觉题。

### 6.3 检索与 Agent 对照

产品对照测实际文本/图文 RAG 工作流的用户收益；结构消融在相同知识内容下比较平面记录和图邻接，不混淆内容增加与结构贡献。

B 为平面图文，BQ 为 B 加共同重排器，C 为图扩展，D 为 C 加同一重排器。固定知识版本、模型、问题、图片权限、初检及每次显式补查的证据块预算（当前6,000 Unicode字符）、最终回答的max_tokens、补查规则和计时口径。证据累计、工具消息及实际模型输入另计，6,000不代表整个对话上限。BQ 与 D 可以有不同召回候选；必须披露访问量和图特征。显式实体实验与端到端识图实验分开。

模块级结构对照还必须冻结同一份检索请求：查询文本、入口实体 ID、条件、ROI 字节及哈希、目标粒度和过滤条件。B/BQ/C/D 重放这些请求，先测检索本身；动态 Agent 的不同改写、补查顺序另作端到端实验。只固定用户原问题而允许四组形成不同检索请求，不能单独归因于图结构。

分三个阶段输出：

1. 首次检索无补查：必要事实/关系/条件覆盖、证据精度、完整证据集合命中；允许等价有效来源。
2. 统一预算补查：新增读取、轮次、调用、证据量、耗时和剩余缺项。缺项发现来自能力契约，不可读取金标准。
3. 最终任务：全部目标完成、条件/数值/引用正确性、状态与库存约束、错误成功、用户确认负担和累计成本。

正式成绩使用冻结且真实审核的预期目标和参考值。原12题和已反复使用的批次保留为开发诊断；原60题是待复核提交集，不能宣称全新盲测。

### 6.4 正式运行前必须冻结的验收协议

协议文件须包含主类别与分母、来源及截图族、开发/留出划分、独立目标和等价证据组、缺参交互脚本、模型/规则/快照版本、重复次数、失败和超时计入方式，以及下表门槛。缺任一项不得开始标为正式的运行。原 60 题继续保留；教师提交数量沿用 V3，独立效用验证必须明确哪些题是新留出、哪些是已曝光回归，不用更换标题制造盲测。

本节新增字段和门槛尚需接入下一版正式协议schema及validate/freeze校验；现有CLI已实现审核和版本门槛，但通过旧版CLI不表示满足本节全部新增条件。该接线属于后续R04/P11工作。

| 维度 | 预先采用的内部验收条件 | 报告方式 |
|---|---|---|
| 完整任务 | 在已声明支持范围内，三轮中的每一轮独立样例全目标成功点估计至少85%，每个预声明主类别至少80%；缺条件题按正确澄清及补参后的续答评分 | 成功须同时满足数值、知识、条件、引用、状态和最终交付；逐轮给分子/分母及95% Wilson区间。门槛针对点估计，不伪称置信下限达到门槛；子目标不折算整题成功 |
| 关键错误 | 冻结负例中无未支持知识冒充确定结论、无错误计算仍宣称完成、无过期结果复用、无伪造审核、无越权库存修改 | 逐个失败归因；任何一项发生即阻止对应能力发布，不用总体平均掩盖 |
| 稳定性 | 相同冻结集及实现完整执行3次，中间不改代码/提示/阈值；不挑选最好一轮，报告各轮和按题汇总 | 不以3N计算独立样本Wilson区间；重复结果按题或截图族聚类分析，另报最差一轮、状态变化和同题成功比例 |
| 建图与来源 | 正式可用的关键记录全部有有效审核及依赖闭包；新页面自动图必须单独测语义正确性/覆盖/ROI对应，纠正后图不能替代自动图成绩 | 按记录类型、来源页组和抽取方式列分母；人工修订负担单列 |
| 图片实际帮助 | 候选确认模式可以发布，但必须在未知名称的独立截图任务中，显示相比同条件文字入口降低名称输入或总交互负担，同时不增加错误完成；自动接受能力另行校准 | 报配对逐题差值、候选命中/集合大小、确认次数和错误接受；若差异不确定，只报告探索结果，不宣称优势 |
| 图结构帮助 | 固定检索请求对照与动态任务对照分别报告；协议须先指定一个主指标及最小实际增益，达到它且无关键错误退化，才声称该任务范围有结构收益 | 证据充分率、全目标成功率、补查成本分别列；配对差异不确定时只报探索，不按结果临时选择指标、最小增益或删题 |

这些是内部产品目标，不是已取得的成绩，也不是虚构教师评分标准。正式运行前的真实审核须确认标签、范围及协议；若样本量不足以支撑优势或安全性结论，报告不确定性并收集新留出样例。正式题一旦因失败而用于修复，立即标记为已曝光回归；修改后的效果验证使用新的留出版本，旧失败保留。

## 7. 硬门槛与效果指标

**以下已定义的完整性测试必须全部通过，失败则阻止相应发布/正式运行：**

- 旧资料与快照不被覆盖；迁移映射、引用、来源、资产、图索引版本一致。
- 正式关键知识与规则批准有效；缺失或循环派生依据不能发布为可用结论。
- 不把候选、合成 fixture、缓存重放或模型自评伪装成人审和正式成绩。
- 任务/目标/ROI/规则变化后旧结果不能仍标有效；错误计划和参数不得静默计算。
- 缺子目标、缺依据或不支持条件不能标成全部完成；计划不能扣除原始库存。
- 测试划分、预期目标、评分口径及阈值在正式运行前冻结；日志中不得输出密钥。

**效果指标须按协议测量：**建图正确性和覆盖、视觉自动接受与拒识、检索证据完整性、任务成功、交互负担、耗时及成本。阈值可在开发样本上校准，随后固定并在留出集报告样本数与不确定性。不能为了通过而事后缩小范围、改标签或扩大允许答案。

“产品有用”的结论需要独立场景中的任务效果或成本改善支撑。图片优势与图结构优势分别成立或不成立；无增益结果进入失败分析，不改写成已证明创新。

没有实际用户实验时，交互次数、名称输入次数与耗时只称为可用性代理指标，不声称已验证真实用户满意度。完整性测试全部通过仅覆盖已定义断言，不等同于所有游戏知识和所有自然语言问题都正确。模型调用轮次、重复失败、修复次数与取消后的副作用边界也必须随运行保存。

## 8. 执行命令与产物约定

现有命令保留。新增命令须先实现、记录 `--help` 并实际运行，不能把下列目标语义当作已有功能：

- 图谱质量诊断、规范化预览/新构建、发布依赖检查、按能力导出审核单。
- 评测 validate / export-review / freeze / run / score / compare；完整保留多轮输入。
- 候选产品样例运行与轨迹导出；失败回归和独立环境复现。

所有实际命令由 `scripts/run_step.py` 记录到 `artifacts/v3/execution.jsonl`，包含代码哈希、退出码、stdout/stderr。新增结果集中于 `artifacts/v3/post_midterm/`，不覆盖中期证据；旧对话中的数值不算本次重新运行。

每项完成须有：代码/配置变化、实际命令、运行模式、产物位置、退出状态、测试结果及剩余限制。状态采用 NOT_STARTED / IN_PROGRESS / PASS / PARTIAL / PENDING_HUMAN / BLOCKED，不用一个笼统百分比代替。

## 9. 人工审核前仍可交付的完整证据包

可以完成代码、工程回归、候选图谱差异、语义依赖报告、原图文并列审核单、候选模型运行、独立数值复核草案、划分校验、逐题轨迹、对照诊断和工作台演练。

不能据此宣称关键知识已经人工批准、正式60题已经通过、独立识别优势已经成立或所有普通问答正确。待审材料应显示原文/原图、候选结论、条件、差异、依赖和实际人工操作入口；由用户逐项或按明确协议审核，不能替用户签字。

人工未完成时继续不依赖审批的工作；正式发布与正式分数保留阻塞原因。

## 10. 讨论来源与执行责任

用户指定的 ChatGPT 对话用于外部设计评审，建议由本地 Codex 结合代码与证据取舍。讨论不构成独立人工审核，也不证明方案已经实现。


本地 Codex 负责计划维护、模块集成、实际运行、证据保存和最终状态报告。不同模块可以并行开发，集成前必须统一接口并审查测试；用户承担需要真实人为判断的知识/规则和评测金标准批准。

### 10.1 2026-11-18 跟进讨论与本地取舍


**优先收紧目标与结论的契约，再优化补查；独立建图与评测数据准备并行。** 网页建议新增目标依据、产物和版本字段；本地复查确认已有相应基础，因此不重复搭框架。下一步重点是静态属性、指定日期计算、阶段剩余区间及用户已声明未知参数的语义区别，以及用户实际收到的答案是否覆盖原请求。工具前提不能自行升级成用户目标。

1. **先做简单知识声明的稳定交付（P06/P07、R01/R02）。** 在现有证据契约上，把主体、谓词、值、单位、适用条件、统计口径和支持记录绑定为可核查声明；派生声明保留实际输入。通用渲染交付简单属性，复杂解释另行核对；一段解释失败不能撤掉无关且有效的结论。结构合法、引用存在和覆盖状态都不能代替语义支持。发布许可继续由服务端独立控制。
2. **据此补齐有界依赖查询（P07/P09、R01/R04）。** 一次显式工具调用可服务多个需求，内部按声明依赖有界展开，但只返回证据与逐需求缺口，不替Agent选目标或执行计算。实际投送给Agent的事实与必要来源才能进入有效证据包；预算外内部发现不能授权计算。记录读取量、展开层次、冲突、剩余前沿及停止原因。比较的全部备选是必需交付，不能与可替代的OR证据分支混同；不能取第一条冲突记录自证。版本、规则指纹与参数绑定沿用现有机制。
3. **用成对正负例验收完整交付，并并行验证融合收益（P03/P04/P08/P11、R00/R05）。** 同时报告完整正确交付、错误成功和不必要拒答，独立期望不取自Agent自身目标。新页面文本/结构锚点/真实像素对照、真实修订、新截图族和可靠原文基线继续准备，不能因Agent改造而搁置图谱质量验证。错配像素只证明系统受像素影响；真实像素改善对齐质量或降低审阅负担，才支持融合收益。

重点新增的通用验收对：用户要求在条件C下比较A/B；A有C条件依据，B只有互斥D条件依据，两条记录均可独立有效且已审。负例必须保留A的有效部分并指出B在C下缺依据，不能输出排名；正例只将B替换为C条件下的依据，应恢复完整比较。把这一检查同时用于简单声明、派生计算、批量补查与最终展示，避免各层各自正确却组合错误。现有条件校验先复用，再补覆盖不足，不将讨论建议记为已完成实现。
