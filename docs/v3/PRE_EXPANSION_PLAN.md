## 四个放行决定

首份覆盖表可从以下四行展开。它们描述不同的知识需求，不能用同一项“页面已导入”统一勾选。

| 玩家要做什么 | 已有可用起点 | 首先应查的缺口 |
|---|---|---|
| 查某作物何时成熟 | 作物页与种子页的季节、基础周期和阶段信息 | 用户问的是总周期、特定日期还是剩余区间；有效生长夜的浇水条件有无引用 |
| 预留献祭物品后处理剩余库存 | 收集包的必选或任选要求、物品售价、任务内库存副本 | 预留数量是否有依据；销售与加工是否使用同一份剩余库存 |
| 比较未经点名的加工方案 | 物品到产物的关系、公式、设备及直接销售价 | 是图中缺了一个产物，还是该产物已经在图中但没有进入答案 |
| 判断能否送给某位村民 | 新领域可以先搜集页面原文 | 在开放赠礼结论前先查人物身份、偏好类别、例外及其优先级；若同类机制缺口过大，单列新页族试验 |

| 决定 | 开始所需证据 | 可推进的范围和失败处理 |
|---|---|---|
| 采集并建立候选原文索引 | 页面身份、来源 URL、获取方式、修订信息和内容哈希可追溯。正文、表格、图注保留定位。采集修订与适用游戏版本分别记录，未知值显式标记 | 可以先扩大资料可搜索范围。记录失败、缺图与别名重定向。来源未固定的条目仅列入待采集目录 |
| 小批建立隔离候选图 | 选定页族与要支持的属性，划定适配批、迁移批、留出组。程序能消费批次清单，输出逐页贡献。实体、关系方向、条件和图像区域的引用可检查 | 可在独立快照运行候选问答。冲突或缺依据的记录进入待审队列。单图识别失败可保留同页有效文本，图像失败仍计入分母 |
| 扩大同一页族的候选批次 | 冻结实现后通过迁移批。重放幂等、替换与撤销可解释、共享来源保留、新进程能回读、旧任务可回放。完成下述针对新增语义的抽检，严重错误已修复且用新样本复核 | 按通过的页族追加候选。个别模板失败时隔离该模板，其他通过的页族可推进。缺语义核对时可以继续离线试导入，扩大范围的质量结论标为待审 |
| 向用户开放指定能力的正式计算 | 该能力的关键事实、条件、派生关系和规则指纹获批，依赖完整。候选和正式权限隔离，结论能追溯至本次实际交付的证据。独立样例达到预先冻结的能力指标 | 只列出获准的能力、条件和版本。其他能力可以继续作候选演练。正式效果门槛及重复运行要求见总计划第 6.4 节 |

## 按依赖执行

| 顺序与工作 | 操作和产物 | 完成判断 |
|---|---|---|
| 1　盘点任务与知识覆盖 | 建立覆盖表。每行写玩家问题类型、期望交付物、所需实体/事实/关系、条件或例外、来源页、已有工具、缺口和验证办法。保留“可搜原文、图中有候选、有足够证据计算、已审核开放”四列 | 对每个缺口能明确下一步是补资料、修抽取、修检索、补规则还是修回答。单页中的单位、计数方式或职业条件只要影响结论，也优先建图 |
| 2　划分批次并登记曝光 | 建立批次清单及曝光账本。记录页族、修订、截图原图或采集会话、派生裁剪、首次查看、用途、冻结实现标识。先定输入和抽检办法再看结果 | 作物与相应种子、同一原图与其裁剪不跨开发和留出组。旧题、旧截图及 Radish 作为已曝光回归。没有独立标注时标明“前瞻候选，待审核” |
| 3　并行准备图谱入口与 Agent 接口 | 图谱侧将已有新页试验改为读取清单，去除页名与图片文件名前缀依赖。按页产出原文、图片出现位置、文本子图、区域观测、融合图及失败清单。Agent 侧先在现有候选库完成下文的条件正负对、部分交付与跨轮纠正 | 采集或抽取中断可续跑，试导入能指定快照且不切换工作台版本。同一用户问题能分别定位所问目标、实际使用的依据、收到的答案和仍缺的内容 |
| 4　适配批试导入 | 建议以一个新作物家族及对应种子页起步。只修改可用于其他同类页面的解析逻辑。在隔离快照检查新增、覆盖、撤销和重复导入，导出完整差异及逐项来源 | 页内多图各自归属正确，数值来自相应表格或原文，阶段顺序和时间条件可追溯。抽取不到、模型超时、空观测与错误对齐分别留存 |
| 5　冻结后做迁移批 | 建议选另外两个新家族，包含一种与适配批有实质差异的结构，例如再收获条件、共享阶段图或表格布局。固定代码、提示、规则、预算、来源和抽检标准后一次运行 | 生成批次差异、工程检查、语义审阅单及失败去向。若须改代码，该批转为开发材料，另选新迁移批验证。某一页族通过只支持同类扩展 |
| 6　联合演练并作放行决定 | 将 Agent 明确绑定迁移候选快照，运行静态知识、开放比较、图像歧义和跨轮改条件各类任务。逐项对照用户实际收到的答案。记录可增加的页族、可演练的能力、待审或暂停的分支及原因 | 候选扩容、正式计算和实验收益各有记录。出现错误成功、错用版本或无法追溯的关键数值，暂停受影响能力，保留对应失败 |

首次小批语义检查建议全核对新增或变更的价格、单位、例外、计算依赖和关系方向；每类视觉证据分别抽取实例，并单列全部超时、冲突和跨资产异常。进入迁移批前，把抽样种子、每类数量、严重错误定义及处理方式写入批次清单。检查同一条边时看原文、原图、框选区域与派生依据。由开发者亲自核对时记为开发者自审。独立语义成绩需要独立标注或审阅。

## 图谱与 Agent 怎样对接

图谱侧提供实体、谓词、值或另一端实体、单位、适用条件、统计口径、支持记录、原文或图像区域定位、快照和审核状态。Agent 在任务侧另记用户原话与请求产物、用户已给或明确未知的参数、任务修订、可见证据包、引用、计算回执和最终交付位置。库存及用户确认仅属于当前任务。

以“预留后比较剩余物品直接出售与加工”为例，用同一份原库存派生计划副本，所有方案使用相同剩余数量、品质、职业和价格口径。检索先从图中发现可加工产物，按用户要求确定要比较的范围，再查公式、设备、设备关系与价格。批量补查可对共享依赖去重，逐方案返回已交付证据、缺参数、冲突或预算缺口。计算只读实际进入证据包的记录。若无法证明所有可行产物都已枚举，答案说明本次覆盖的范围。

甜瓜是已有的定位样例。当前快照中，果酒和果酱各有旧来源迁移与按类别和公式推导的加工边。展示方案需按产物及适用条件归并，审计保留各条支持路径。更多边数并不代表更多加工方案。此前实际运行遗漏果酱，开发时应定位证据投送、计算或交付环节。[开放比较的真实结果](../../artifacts/v3/post_midterm/evaluation/final-v4b-open-comparison/OPEN-01.json)

| 检查 | 可观察的预期行为 |
|---|---|
| 两个方案均有同条件的完整依据 | 用户收到两项结果、直接出售的参照以及所问解释。后台有计算回执只算中间进度 |
| 只把一个方案的依据换成互斥职业或品质 | 保留有效方案，指出另一项缺哪个条件的依据，停止总体排名。恢复匹配来源后应恢复完整比较 |
| 玩家将数量改小或取消预留 | 新一轮按新条件重算，旧回执失效，原库存不被扣减 |
| 玩家只问总周期，或明确不知道阶段内经过天数 | 总周期使用有来源的静态声明。需要推测剩余时长时，有适用规则就给区间；身份有歧义才请求对应确认 |
| 撤销唯一来源，或撤销重复支持之一 | 唯一依据消失时撤回受影响结论；另有独立有效来源时保留仍受支持部分。旧任务能按旧快照回放 |

## 建图、图片和产品效果怎么验

- **建图收益。** 在预选新页面上固定文字、图注、版式和 Semantica 流程，对比仅文本、保留图注与链接的结构组、加入真实像素的融合组；再用错配像素检查系统对图像的依赖。核对实体/状态/关系方向、区域误配、条件遗漏及人工修改量，分别报告自动输出和修改后结果。视觉失败计入原分母。错配干预有反应只能说明像素参与，真实像素带来质量或审阅成本改善才支持收益。
- **检索与回答。** 相同查询、入口实体、条件和 ROI 回放固定请求，比首轮充分证据和显式补查。整题另行运行动态 Agent，记录完整正确交付、错误成功、合理澄清与不必要拒答。原文基线先去除导航噪声。可用人工核对的证据包做单独诊断重放，正常产品运行不读取参考答案。
- **独立测试与玩家自由提问。** 正式留出组与适配、迁移两批另外分组。允许冻结的导入器读取留出页面来建评测库，禁止用留出标签或失败反馈调参后继续报告盲测。图库标准精灵图与独立玩家截图用途不同。玩家可在固定版本自由提问，保留原话、截图、续问、纠正和最终反馈。玩家是否解决需求、答案语义是否正确、知识是否批准分别记录。没有真人参与时，先完成证据扰动、算术回归、增量回放和候选审阅包。

失败按最近的证据断点分流。来源本身缺项就补来源；来源正确而图中错漏就查抽取和对齐；图中已有而检索包缺项就查召回、条件筛选和预算；证据正确而值算错就查规则；回执正确而最终漏答或误判目标就查 Agent 和展示。每次修复保留旧失败，另建输出目录。

## 第一批执行入口

已有的[增量集成器](../../scripts/post_midterm_integrate.py)可接收完整页贡献。试导入用当前候选对应的注册表，其 `snapshot_id` 指向父候选，`identity.base_snapshot_id` 给出 `--base-snapshot` 所需的基线。传入新页 `--document` 和新的 `--label`，该路径使用 `activate=False`。现有[新页试验](../../scripts/post_midterm_new_page.py)含 Radish 固定清单和文件名过滤，通用清单入口列为步骤 3 的开发项。现有[图文审核包](../../scripts/post_midterm_review_packet.py)以代表性记录为主，还需按本批完整差异导出关键条目。

执行时复用 `scripts/run_step.py` 保存命令、退出码、日志与实现版本。集成后以明确的候选 ID 运行 `graph-audit`、`release-audit` 和[新进程回读](../../scripts/post_midterm_reproduce.py)。用[评测入口](../../scripts/post_midterm_evaluation.py)执行协议校验及候选诊断。新版正式协议的额外门槛仍须接入校验器。首轮交付物依次为覆盖表、批次与曝光清单、接口正负对、隔离快照和差异、逐项审阅包、按页族及能力签发的放行记录。

本次 Pro 评审采纳了两项调整。结构化优先级按结论依赖决定，单页的单位和例外同样值得优先处理。候选批扩大只需证明相应页族可稳定迁移，证明像素有收益和开放正式计算各走自己的验收流程。
