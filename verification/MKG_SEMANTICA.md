# mKG-RAG × Semantica 专项核验

结论：**本项目设计的 Wiki 工程适配路线已真实走通；完整论文复现和相对基线的收益没有得到验证。** 可执行专项检查 `python -m verification.probes.mkgrag_semantica_probe` 的 22 项断言通过，原始记录见 `results/mkgrag_semantica.json`。这里的“走通”包括图片候选进入真实图谱、页面到图的检索、实体/关系/子图证据、来源追踪与计算依赖。

## 谁负责什么

| 设计部分 | 实际执行方式 | 证据和边界 |
|---|---|---|
| 知识构建 | 从冻结 Wiki DOM 提取事实、实体和关系，交给 Semantica `GraphBuilder.build(extract=False)` | `knowledge.py`、`graph.py`；真实调用与输入输出逐字段比较 |
| 来源持久化 | 显式使用 Semantica `ProvenanceManager` 的 SQLite 存储 | 71 条事实保存原文、位置、修订 URL、哈希；独立进程读取 |
| 图文对齐 | Wiki 标准图片 → 对应实体/生长阶段 → 页面出现位置 | 37 个图片资源、872 个对齐的出现位置；HTML 布局对齐，不是从像素自动推理全部关系 |
| 第一阶段 | 中文别名、目标关系和视觉候选共同选择至多 5 页 | 实际的词法/规则评分；未实现学习式多模态 embedding 或原版 QM-Retriever |
| 第二阶段 | 从这些页面的受限事实集合构造候选图视图，最多 3 跳、30 个领域节点 | `retrieval.py`；页面范围、卡片预算和领域边访问均留下轨迹 |
| 多粒度 | 实体卡、关系/事实卡、查询子图 | 输出真实 `node_ids`、`relationship_ids`、图片和事实 ID，均可反查同一 Semantica 导出图 |
| 问题感知 | D 仅对 C 的相同候选池做目标关系重排 | 16 题的 C/D 候选哈希一致；没有把新证据混入 D |
| 计算和回答 | 从实际图事实解析参数，纯函数计算，ChatECNU 组织回答 | 相关价格干预改变结果；删关键依赖会拒算；真实 function calling 往返通过 |

论文第 3.2.2 节是在第一阶段候选文档的图上做实体、关系匹配及有界扩展；第 3.2.3 节的 QM-Retriever 包括视觉编码器、Question Converter 和 Q-Former。本轮使用固定 Wiki 图谱的查询视图、模板匹配和确定性评分来验证工程连接，**没有训练/加载原论文 QM-Retriever，也没有执行 EGTR 场景图生成**。不能将这些工程替代称为原算法复现。依据：本地 `资料/2508.05318v2.pdf` 和用户完整计划第 4 节。

## 一条真实可追踪的路径

输入是 `data/visual_crops/V28.png`，从 Steam 玩家攻略截图的背包种子格裁剪而来。模板读取图片像素，第一候选为 `Parsnip_Seeds`，并关联真实 Wiki 参考图与 occurrence ID。

```text
真实截图 V28
  → 像素候选 Parsnip_Seeds
  → Wiki 种子图及其页面出现位置
  → Parsnip_Seeds --GROWS_INTO--> Parsnip
  → Parsnip --HAS_FACT--> fact:Parsnip:growth_days
  → fact:Parsnip:growth_days --SUPPORTED_BY--> source:Parsnip
  → value=4，unit=growth_nights，原文位置 #infoboxtable row[Growth Time]
  → 页面修订 oldid=191123
```

上面的箭头是实际导出图中的关系，专项 JSON 保存每条边的稳定 ID 和属性。来源 SQLite 保存的事实记录与图中事实逐字段相同。图中也有独立的 `Season` 节点、`GROWS_IN_SEASON` 关系，以及从作物类别和机器输入规则派生的 `CAN_PROCESS` 关系；加工关系注明其支持事实，避免把“所有作物都可以酿果酒”这样的假设写进图。

相同截图分别问“这是什么种子？”和“春季种下它，需要多少个生长夜晚？”，实际结果不同：前者优先种子实体与种子→作物关系；后者包含作物季节、生长夜晚和浇水前提。不是只修改回答措辞；保存的最终事实 ID 集合确实变化。

再输入春 23 日、50 株、每天浇水、无加速、普通品质等条件，图谱提供 4 个生长夜晚、种子 20g、出售 35g 和季节规则，计算得到春 27 日、种子成本 1000g、销售额 1750g、只扣种子成本收益 750g。隔离副本将售价改成 40g 后收益变成 1000g；删除种子→作物边则拒算。测试修改标为 `test_override`，没有反写 Wiki 原始快照。

## 五种原始资料对齐例子

专项 JSON 保存了防风草、甜瓜、蓝莓的阶段表，以及高品质作物收集包、酒桶配方，共五种例子。阶段图提供外观，表头和时长行提供阶段顺序与持续时间；献祭表中三个 slot 图片出现位置支持 choose-3 结构；配方数量来自 HTML 表格。原始图片提供实体和状态线索，关系和数字主要来自布局及文字。**这些材料支持图文状态对齐，不支持“仅凭图片自动恢复全部知识关系”的宣传。**

## 目前没有证明的事

平面图文基线 B 与图谱重排 D 在本轮 14 道可回答题中都完整覆盖 10 题的必要证据；粗排图谱 C 为 5 题。D 对 C 的改善说明粗排需要修正，尚不能证明“加图谱比平面检索更好”。两个缺身份题被 B/C/D 正确要求补充。具体配对结果保留在 `results/retrieval_scores.jsonl`，不从结果中只挑获胜案例。

当前两阶段受控检索仍会漏掉浇水或加工时钟等跨页前提。实际计算流程会显式补齐至多 12 个依赖事实，并记录补查；这项运行时补查没有计入受控 D 的成绩。未来应通过新的开发题改进页面召回和依赖完整性，再用未见过的题检验。

视觉测试规模、游戏版本和独立审核尚不满足原核验合同；阶段最终需要用户确认。本次结论是“支持继续做限定范围的课程原型”，不是“全计划已经验收”或“方法论文效果已经复现”。
