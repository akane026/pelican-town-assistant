# 星露谷助手技术可行性核验计划

编制日期：2026 年 11 月 12 日。适用项目：课程第五题“专业领域问答与计算助手”，当前候选领域为星露谷物语。目标是在有限真实资料、有限截图和本机资源下，判断 Semantica 图谱、图文检索与确定性计算能否连成可复现的技术链，再决定完整应用的开发范围。

用户已授权执行核验、配置本机环境、使用网上真实截图，并提供 ChatECNU 接口与密钥。现已执行 V01—V08 的可运行分支；V02 的真实构图/来源/独立重载通过，其余涉及数据版本、样本规模、独立审核和方法收益的验收按真实范围标记，详见 [REPORT.md](REPORT.md)。原始 48 图及其他完整验收门槛保留，不因小样成功而降低。专门的 mKG-RAG × Semantica 连接核验见 [MKG_SEMANTICA.md](MKG_SEMANTICA.md)。本轮交付可运行核验原型和报告，不自动进入完整网页应用开发。

## 1 范围和判定对象

核验围绕两个代表任务展开：一是“文字加种子截图，计算成熟日期与基础收益”；二是“文字加作物阶段截图，返回剩余生长区间或澄清问题”。加工价值、献祭库存和设备材料用小型规则用例检验数据结构与计算边界。每项结论必须限定到实际版本、实际样本和实际使用的方法。

首批候选页面为 Crops、Parsnip、Parsnip Seeds、Melon、Keg、Preserves Jar、Bundles，按阶段、再生和设备测试需要补充 1—5 页，最多 12 页。先覆盖少量春夏作物、两类设备和必要献祭规则；PC 原版、室外、无模组是拟定范围。游戏确切小版本、页面修订与支持规则须分别冻结，不能用抓取日期替代版本。

本轮不训练 QM-Retriever，不安装整套论文训练环境，不抓取全站，不实现完整前端，不宣称全局最优经营。课程选题页的 20 题属于示例，最终提交页要求 60 题逐题结果；本轮小样用于验证技术可行性，不能替代正式评测。

外部模型预算已按用户后续明确授权更新：ChatECNU，文本模型 `ecnu-max`、视觉模型 `ecnu-plus`。本轮设置 100 次调用和每次最多 1024 输出 token 的执行上限，实际调用 34 次；使用公开游戏图片和核验问题，密钥仅保留本地 `.env`。用户说明额度充足，此授权覆盖本轮测试。未租用计算资源、训练模型或下载多 GB 权重。实际能力按探测记录判断，不从模型昵称推断支持范围。

核验采用两条独立结论轴：

| 结论轴 | 要回答的问题 | 成立所需依据 |
|---|---|---|
| 工程可行性 | 能否获取资料、真实建图、匹配截图、检索、计算并离线重跑 | 可执行产物、正确性断言、错误路径、重载及端到端轨迹 |
| 方法贡献 | 图结构、阶段对齐和问题感知重排序相对平面图文检索是否有初步价值 | 固定数据和预算下的逐题配对结果、证据完整性和失败解释 |

工程可行不代表方法优于基线；小样没有收益也不自动代表系统不能开发。无数据、无截图或尚未运行时，保持未验证，不用推测填补结论。

| V04 的组间边界不够严格 | 固定 A/B/C/D，D 只对 C 的相同候选重排 | 防止把额外候选、模型或计算知识归因给重排序 |

| 图导出与来源持久化混为一项 | 图 JSON、来源 SQLite、manifest 共同交付；独立进程重载 | 导出图成功不能掩盖来源丢失 |

P0 表示本轮核心判定必需，P1 表示底座后执行的研究或资源验证，P2 表示可选扩展。优先级不是允许省略的证明等级：V04 虽在底座之后执行，仍是当前方法方案的必查项；V07、V08 的核心复跑不能因编号较后就跳过。

V02 不依赖文档示例中的隐含持久化：`GraphBuilder` 主要返回图结构字典，不能假设其具有原生 query、save、load 契约；`GraphBuilderWithProvenance(provenance_manager=...)` 的文档写法与已检查源码存在差异，注入 manager 未形成预期调用，默认内存来源存储、异常处理及 `source=graph_construction` 也不足以证明真实出处已保存。[图构建源码](https://github.com/semantica-agi/semantica/blob/39cf7216d2326b012436efebf8a227e82f37dd3b/semantica/kg/graph_builder.py)；[图来源包装源码](https://github.com/semantica-agi/semantica/blob/39cf7216d2326b012436efebf8a227e82f37dd3b/semantica/kg/kg_provenance.py)。

拟定主路径为实际 `GraphBuilder` 构图，加显式 `ProvenanceManager(storage_path=...)` 保存事实与真实页面证据，再保存图 JSON、来源 SQLite 和联合 manifest。查询可使用从该构图结果派生的 NetworkX 视图，必须在日志中说明调用边界。`SQLiteStorage` 是来源存储相关组件，不是默认 Neo4j 的 `GraphStore` 替代品；首轮不启用图数据库服务。[来源管理源码](https://github.com/semantica-agi/semantica/blob/39cf7216d2326b012436efebf8a227e82f37dd3b/semantica/provenance/manager.py)；[JSON 导出源码](https://github.com/semantica-agi/semantica/blob/39cf7216d2326b012436efebf8a227e82f37dd3b/semantica/export/json_exporter.py)；[来源文档](https://docs.getsemantica.ai/reference/provenance/)。

只安装核验所需组件，不使用 `all` 或整组可选依赖。基础包仍可能带 NumPy、Pandas、SciPy、PyArrow 等依赖，须记录实际解析出的包和安装体积，不能预称“轻量”。论文仓库原环境涉及 Python 3.10 和 EGTR，作为方法参考，不整套复制进课程环境。[mKG-RAG 官方仓库](https://github.com/xandery-geek/mKG-RAG)。

## 4 状态 数据审核与执行记录

| 执行状态 | 使用条件 | 是否计作通过 |
|---|---|---|
| NOT_RUN | 尚未执行该项 | 否 |
| IN_PROGRESS | 已开始，尚无最终判定 | 否 |
| PASS | 全部预先冻结的必测断言满足，有本次真实运行证据 | 是 |
| PARTIAL | 已执行，只有部分子项满足；缺口逐项列出 | 否，不折算为完整 PASS |
| FAIL | 实际结果违反必测断言 | 否 |
| BLOCKED | 有明确的必需外部条件缺失，无法执行相应子项 | 否 |
| SKIPPED | 主动不做非必测项，写明理由 | 否 |

每个 V 项拆成子检查，聚合结果同时展示通过数、失败数、阻塞数、未运行数。不能因 Python 进程退出 0 就把整个 V 项设为 PASS。某项超过修复时盒，保留已观察到的 FAIL 或 PARTIAL，并记录剩余问题；不能仅凭耗时宣布技术不可行。

数据审核另用 `candidate / verified / conflict / rejected / superseded`。来源真实性、数值核验和独立人工审核分别记录方法与日期；没有人工复核时写 pending，不编造审核人。执行 PASS 不会自动把候选事实变成 verified。正式计算只接受支持版本与条件明确、证据可定位的已核准事实。

每次运行至少记录 `run_id`、开始结束时间、命令参数、退出码、脱敏 stdout/stderr、输入哈希、知识快照 ID、图及索引构建 ID、代码版本或脚本哈希、依赖锁哈希、配置哈希、产物路径和断言结果。尚无 Git 时写 `git_status=not_initialized`，不使用虚构 commit。模型配置只记非敏感键名和能力状态。

### 5.1 视觉样本

目标为 48 张经过人工标签核对的真实游戏局部截图，按源截图、游戏会话和连续帧分组划分。一个源图的裁剪、缩放、加边框版本只能在同一侧，不能各算独立真实样本凑数。

| 类型 | 合计 | 开发集 | 冻结测试集 |
|---|---:|---:|---:|
| 物品与种子 | 24 | 8 | 16 |
| 作物生长阶段 | 12 | 4 | 8 |
| 图库外未知物品或阶段 | 12 | 4 | 8 |
| 合计 | 48 | 16 | 32 |

图库可以包含被测试物品的 Wiki 标准图，这是闭集检索；不能称作未见类别泛化。每条样本包含原图来源、授权使用范围、局部坐标、实体/阶段候选、数量与品质是否可见、人工标签状态、分组 ID 和 split。第三层 12 张全部为图库外 unknown，保证未知拒识分母固定。歧义作为前两层已知样本的预标标签，开发至少 2 张、测试至少 2 张，物品与阶段分别至少覆盖一例；人工可通过原截图上下文确认实际对象，但局部图不足以唯一确认时应保留候选。不能把“图库没有正确类别”和“图像信息不足以区分类别”混为同一种错误。

只在开发集调整预处理、阈值和候选数量。测试前保存清单与配置哈希；之后发现错误可以修复再跑，但原轮次保留，说明已查看测试集及受影响范围。用户确认前的候选准确率、自动接受覆盖率、确认后的任务成功率分别报告。缺真实截图时，该子项 BLOCKED；Wiki 原图自查与合成扰动只作为开发健全性检查。

### 5.2 检索问题与正确证据

固定 4 道开发题和 16 道测试题，测试构成 8 个配对组：4 组同图异问、4 组同问异图。主标签覆盖身份、属性、阶段、跨页面关系、需要计算的证据依赖、多义图和缺证据，单题可以有多个副标签。各方法面对完全相同的原始输入、状态补充脚本和知识快照。

下表用于取得资料后的出题，先独立标注证据，再冻结具体措辞。每组两题，同组不得跨开发/测试划分。

| 测试配对组 | 唯一变化 | 两题所需的证据差异 |
|---|---|---|
| R01—R02 种子身份与种植 | 同图，改变问题 | 种子实体与图标；种子到作物、季节及生长规则 |
| R03—R04 收成出售与献祭 | 同图，改变问题 | 品质售价；献祭要求、最低品质、数量及完成状态 |
| R05—R06 加工价值与完工 | 同图，改变问题 | 加工售价规则；设备、时钟、截止条件 |
| R07—R08 阶段识别与成熟 | 同图，改变问题 | 阶段候选；后续阶段、持续时间与生长前提 |
| R09—R10 不同种子的种植 | 同问，改变图片 | 对应作物、季节和生长规则随种子改变 |
| R11—R12 不同阶段的剩余时间 | 同问，改变图片 | 阶段及后续阶段集合随图片改变 |
| R13—R14 已知与未知对象 | 同问，改变图片 | 有效实体证据；未知对象拒识与缺证据状态 |
| R15—R16 明确与多义加工品 | 同问，改变图片 | 原料可确定时的规则；原料不明时的澄清依据 |

同图异问固定图片字节、裁剪、视觉候选、玩家状态和知识快照，仅改变文字目标。同问异图固定问题与状态，仅换图片。两题各自满足正确证据要求才算配对通过；子图发生变化本身不算正确。

正确证据标注允许等价来源集合：对每个必需事实给出可接受证据候选，另列必须共同成立的条件与合法组合。完整性要求至少覆盖一组充分且条件一致的证据组合，不强制唯一页面 ID，也不把互相矛盾的零散证据拼成完整答案。缺证据题的 gold 明确缺失项及允许的澄清/拒答，不用不存在的答案计算召回率。

开发题、测试题、gold、预期证据 ID 和人工标签不进入运行索引、图库附加文字或在线工具。测试检索器只读取问题输入；评分程序在结果落盘后读取 gold。固定配对案例先于运行选定，不从结果中挑两题展示优势。

| 方法 | 可访问输入与机制 | 比较用途 |
|---|---|---|
| A 纯文字检索 | 原始文字问题与允许玩家状态，词法/文本检索；不接收图像候选或图扩展 | 测量不使用视觉时的证据覆盖；不是旧计划 B0 通用模型，也不是旧 B1 识图后文字 RAG |

必要证据集合完整率为“至少覆盖一组合法充分证据的可回答题数 / 可回答题数”。部分事实召回可对最佳合法证据方案计覆盖率，但不能混合互斥方案。页面、图片和关系召回只对有相应 gold 的题计分；缺证据题独立报告正确澄清/拒答率。逐题列 B→C、C→D 的改善、持平、退步，并按配对组汇总，避免把共享图片的两题当作独立泛化证据。

工程门槛为 16 题轨迹完整、预算与候选约束通过、至少一组同图异问产生与目标一致的证据变化，缺证据不被编造补齐。方法贡献不设“必须正增益”硬门槛：列出配对改善、持平、退化和失败原因，结论采用“有初步证据/尚不明显/当前资料不适合该主张”。小样不宣称统计显著。

干预只发生在隔离副本：建立 `test_override` 新快照，记录原值、改值及测试原因，不伪造新的 Wiki 原文。改变相关基础价格应改变图读取输入及对应结果，引用必须指向测试快照；改变无关事实不应改变目标结果。删去唯一关键关系/规则时拒算或有界补查，存在其他合法路径时给出替代依据。

来源另测三种情形：删除唯一有效来源后不得继续正式计算；删除一个冗余来源后如另有充分有效证据可继续，但失效引用消失；原文或图片文件缺失、哈希不符时必须发现证据损坏。更换快照后旧索引/缓存必须失效或明确拒绝，禁止结果仍从旧缓存返回。原始快照只读，所有干预结束后不反写正式库。

门槛为 12 类场景及已冻结子例全部满足断言，日志证明参数来自真实图读取；人工审核未完成则验收状态单列，不声称完整独立复核。产物为 `probes/calculation_probe.py`、独立 gold、`results/calculation_cases.jsonl`、干预 manifest 与前后差异。失败先定位来源/条件、取整/时钟、库存或缓存层，不把计算移交 LLM 回答。

## 14 V08 离线重跑与最终决策

**状态：PARTIAL：严格离线复跑通过，完整合同缺口对应退出码 2。优先级：P0。依赖：V00—V07 的实际记录，不要求所有可选项通过。** 假设是另一进程能仅依靠已交付文件重载知识、执行核心查询、检索、计算及回放，且报告可追到每个原始结果。

统一 CLI 已实现为 `python -m verification.run_all --offline`，并已真实执行；详细运行命令和退出码见 README。区分在线采集/探测与离线执行：offline 严格禁止网络，不自动 pip 安装、不下载模型、不请求 API；读取已冻结本地输入并重新计算。缺素材时返回具体 BLOCKED，不复制历史结果假装本次运行。在线专属步骤可按协议跳过，但核心本地步骤必须执行。

每阶段原子写入检查点。只有输入、代码、配置、schema 和依赖哈希一致时才允许复用上游产物；变化使受影响阶段及下游失效。报告区分“本次重新执行”和“复用已验证输入”，图/索引/缓存版本不符不能静默混用。中断重跑不重复追加同一结果，部分下载和不完整构建不得发布成正式快照。

运行器退出码合同拟为 0 表示全部选定必测断言通过，1 表示存在必测失败，2 表示未失败但存在必测阻塞/未运行，3 表示配置或运行器自身错误。具体值实现时写入 README；汇总仍以逐项记录为准，SKIPPED 不计入成功分母。
